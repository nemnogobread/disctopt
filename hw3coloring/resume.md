# Отчёт: задача о раскраске графа (hw3coloring)

## Постановка

Нужно минимизировать число цветов в раскраске графа так, чтобы любые две соседние вершины имели разные цвета.

## Первая итерация (без эвристик)

**`ColoringSolver.java`**:
- **Точный DP по подмножествам** для относительно малых графов (`n <= 70`).
- Для больших графов — **простой жадный алгоритм**: вершины сортируются по убыванию степени, после чего каждой вершине назначается минимальный допустимый цвет.

На малом тесте: для `data/gc_4_1` решатель возвращает **2**

## Результаты прогона `ColoringSolverChecker`

Запуск на наборах из чекера (значение — найденное число цветов):

| Файл | Результат |
|------|-----------|
| `data/gc_50_3` | 5 |
| `data/gc_70_7` | 6 |
| `data/gc_100_5` | 21 |
| `data/gc_250_9` | 97 |
| `data/gc_500_1` | 18 |
| `data/gc_1000_5` | 124 |

Для gc_50_3 и gc_70_7 динамика дала решение даже за небольшое время, а остальные случаи надо дорабатывать эвристиками.

## DSATUR эвристика

По сути это более осмысленный жадный алгоритм - красить сначала вершины с наибольшей насыщенностью, те с наибольшем количеством закрашенных соседей. 

| Файл | Результат |
|------|-----------|
| `data/gc_50_3` | 5 |
| `data/gc_70_7` | 6 |
| `data/gc_100_5` | 18 |
| `data/gc_250_9` | 93 |
| `data/gc_500_1` | 16 |
| `data/gc_1000_5` | 115 |

Видно, что результаты улучшились, но всё ещё нужно дорабатывать решение (второй порог не везде достигается).
